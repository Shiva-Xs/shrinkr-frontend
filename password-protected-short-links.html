Password-protected short links

Sometimes a short link needs a lock on it. Shrinkr lets you put a password in front of any URL, so the redirect only happens for someone who knows it.

Set the password in the same step where you create the link — the --password option sits next to the URL field. The link is protected from the moment it exists, so there is no window where it is public before you get around to locking it.

What a visitor sees

Opening a protected link does not redirect. It serves an unlock page asking for the password. Enter the right one and the redirect follows immediately; enter the wrong one and nothing is revealed. The destination URL is never included in the unlock page — it stays server-side until the password checks out, so it cannot be pulled out of the page source.

When this is the right tool

  • Sharing a document with a small group where a link alone is too loose but a full auth system is too much.
  • Posting somewhere semi-public and wanting the password to travel through a different channel than the link.
  • Draft or preview URLs that should not be crawlable or forwardable.
  • Time-bound access, by combining a password with an expiry date or a click cap.

What it is not

A password on a link is access control, not encryption. It keeps casual visitors and crawlers out of a destination, and it is the right size of tool for sharing something that is merely private rather than genuinely sensitive. If a leak would actually hurt — credentials, financial records, anything regulated — use a system built for that and not a link shortener.

Combining it with other limits

Password, expiry date and click limit are independent, and any combination is allowed. A password plus a two-day expiry gives you a link that needs a secret and stops working on its own. A password plus a click limit of one gives you something close to a single-use handoff.

All three are editable afterwards from the manage page, as long as you still hold the manage token issued when the link was created.

Questions

How do I put a password on a short link?

Set the password at creation time, using the password option next to the URL field. The link is created already locked. Visitors who open it see an unlock page and must enter the password before the redirect runs.

Can I add or change a password after the link exists?

Yes, from the manage page, using the manage token you received when the link was created. You can add a password to an unprotected link, change it, or remove it entirely.

Does the destination URL leak before the password is entered?

No. The unlock page does not contain the destination. The redirect is only issued after the submitted password is verified server-side, so the target URL is never sent to a visitor who has not unlocked it.

Is password protection free?

Yes. There are no paid tiers on Shrinkr, so passwords, expiry dates, click limits and QR codes are all available on every link at no cost.
